SECURITY

Security is part of the build.

Security cannot be guaranteed by a static website alone, so DWL uses practical safeguards and recommends secure hosting configuration.

🔐 HTTPS

Use HTTPS on the production domain so browser traffic is encrypted.

🛡️ Spam protection

The contact form includes basic client-side validation and a honeypot field. Production forms should also use server-side validation, rate limiting and CAPTCHA or an anti-spam service.

🍪 Cookie consent

The site asks visitors for cookie preferences before storing a preference in local storage.

🔎 Privacy

Privacy and terms pages explain how the website should be used and what visitors should understand.

⚙️ Secure hosting

Keep hosting, DNS and third-party integrations updated. Never put passwords, API keys or private credentials inside frontend code.

Important: Frontend JavaScript alone cannot provide complete spam or security protection. If you connect this site to a real form backend, add server-side validation, rate limiting and secure storage.
